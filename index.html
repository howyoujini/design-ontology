두 개의 질문

질문마다 7단계 과정이 있어. 첫째는 문서의 문장 하나가 회사의 결정이 되어 실제 값과 비교되기까지, 둘째는 기본 약속 하나가 검사와 숫자가 되기까지. 단계를 하나씩 눌러봐.

Class — 이 모델에 존재하는 것의 종류, 서른일곱 개

박스 하나가 Class — 이 모델에 존재하는 것의 종류 — 하나야. 가로 띠 여덟 개는 비슷한 역할끼리 묶은 층이야.

Interface — 여러 Class 가 같이 지키는 계약

여러 Class 에 똑같이 적용되는 조건이 있어. "담당 팀이 있어야 한다", "버전이 있다", "기록은 고칠 수 없다" 같은 것. 이런 조건을 Class 마다 반복해서 적는 대신, Interface 에 한 번만 적어두면 그걸 따르는 Class 전부에 적용돼. 카드를 누르면 어느 Class 들이 그 조건을 따르는지 맵에 표시돼.

Relation — Class 를 잇는 연결, 쉰다섯 개 전부

Class 와 Class 를 잇는 연결의 종류야. 연결이 출발하는 Class 를 정의역(domain), 도착하는 Class 를 치역(range)이라고 불러. 하나를 누르면 그 연결만 맵에 그려져 — 이름이 비슷한 연결들이 실제로 어떻게 다른지 비교할 때 쓰면 좋아.

Inference — 적지 않아도 참인 것

기록된 연결(Relation)을 이어서 따라가면, 직접 적은 적 없는 사실도 알아낼 수 있어. 그렇게 알아내는 방법 일곱 가지야. 카드를 누르면 어떤 연결을 따라가는지 맵에 그려져.

Action — 사람이 뭔가를 바꾸는 유일한 방법

사람이 결정으로 무언가를 바꾸는 방법은 열 가지뿐이야. 동기화·추출 같은 자동 실행은 결정이 아니라 관찰 기록을 만들어. 각각에는 실행 전에 확인하는 조건(Axiom)이 정해져 있고, 조건을 만족하지 못하면 실행 자체가 거부돼. 맵에서 보기를 누르면 그 Action 이 무엇을 바꾸는지 맵에 표시돼.

Metric — "잘 되고 있나?"의 답

Axiom — 언제나 지켜져야 하는 조건

항상 지켜져야 하는 조건들이야. 어기는 데이터는 경고가 아니라 아예 만들 수 없어. 카드를 누르면 그 조건이 어느 Class 에 적용되는지 맵에 표시돼.
