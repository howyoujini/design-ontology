Design System Ontology · v5

하기로 한 것과 실제로 있는 것,
그 사이를 재는 모델

이 모델이 답하려는 질문은 둘이야. "우리가 뭘 하기로 했고, 현실이 그걸 따르고 있나?" 그리고 "지키기로 한 걸 실제로 검사하고 있나?" — 34개 클래스는 전부 이 두 질문에 답하기 위한 부품이야. 실제 데이터는 없고 구조만 있어.

두 개의 질문, 두 개의 여정

첫째 여정은 문서의 문장 하나가 회사의 결정이 되어 현실과 비교되기까지, 둘째 여정은 출발 약속 하나가 검사와 숫자가 되기까지야. 걸음을 하나씩 눌러봐.

Class — 이 모델에 존재하는 것의 종류, 서른네 개

아래 맵의 박스 하나가 Class 하나야. 여덟 개 밴드는 Class 들을 역할별로 묶은 층이고.

예시는 아틀라시안 공개 문서(ADS)를 바탕으로 구성한 것 — 실제 내부 데이터가 아니야

박스를 누르면 그것이 무엇과 이어지는지 보여 · 점선은 직접 만들 수 없는 공통 이름 · 초록 밴드가 "하기로 한 것", 주황 밴드가 "실제로 있는 것" 쪽이야

Interface — 여러 Class 가 같이 지키는 계약

"주인이 있어야 한다", "판이 있다", "기록은 못 고친다" — 여러 클래스에 똑같이 적용되는 조건을 클래스마다 반복하지 않고 여기서 한 번만 선언해. 프로그래밍의 인터페이스와 같은 개념이야. 카드를 누르면 그 계약을 구현하는 클래스들이 맵에 표시돼.

Relation — Class 를 잇는 연결, 마흔두 개 전부

온톨로지에서 object property, Foundry 에서 Link Type 이라 부르는 것 — Class 와 Class 를 잇는 연결의 종류야. 화살표의 출발 Class 를 정의역(domain), 도착 Class 를 치역(range)이라고 불러. 누르면 그 연결 하나만 맵에 그려져. 이름이 비슷한 것들이 실제로 어떻게 다른지 비교할 때 써.

Action — 뭔가를 바꾸는 유일한 방법

이 모델에서는 아무거나 직접 고칠 수 없어. 바꾸려면 여덟 개 문 중 하나를 지나야 하고, 문마다 지켜야 할 조건(공리)이 걸려 있어 — 조건을 못 맞추면 문이 안 열려. 맵에서 보기로 각 문이 뭘 건드리는지 확인해.

Metric — "잘 되고 있나?"의 답

Axiom — 언제나 지켜져야 하는 조건

어기면 의견 차이가 아니라 "만들 수 없음"으로 처리되는 조건들이야. 초록 띠가 이번에 새로 들어온 것들이고, 카드를 누르면 어디에 걸리는지 맵에 표시돼.
